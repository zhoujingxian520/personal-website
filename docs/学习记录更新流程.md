# 学习记录更新流程

## 怎样提出更新

直接说：“把这份资料整理成学习笔记，更新网站并同步 Git。”附上资料、文件或可访问的对话引用。补充同一主题时可说“更新某某主题原来的记录”。

执行者整理材料到 src/content/learning 中：同主题更新原文件，新主题新建文件，日期记录本次更新日期，正文包含本次学习内容、知识要点、待解决问题、下一步。不会把生成的解释当作你已经掌握的知识。没有说明状态时，旧记录保持原状态，新记录默认计划中。

## 六级翻译笔记

说“更新六级翻译”即可从 [Work 主笔记](../notes/cet6-translation.md)生成网站和离线预览。Work 依据[六级翻译笔记模板](templates/六级翻译笔记模板.md)维护同一份 Markdown。也可以在更新时明确提供新版文件。

1. 确认本次来源可读取，并与最新远程 `main` 上的主笔记比较。修订沿用原编号，新增内容用新编号。发现已有编号消失时，先确认对应的删除或换号。首发以仓库内的空白主笔记为起点。
2. 审阅本次拟公开的笔记差异，执行 `npm.cmd run update:notes`。检查会在导出前验证格式与引用。成功后直接打开 `outputs/网站预览/index.html`，从学习记录进入六级翻译，检查本次内容与双向跳转。
3. 只提交本次相关的笔记和必要源码，按现有流程推送 `main`。工作区有其他在制改动时，从最新远程版本另行检出，并只带入本次内容。推送后核对对应的 GitHub Actions 部署和公开翻译页。

## 检查与生成网页

在项目根目录运行：

```powershell
npm.cmd run update:notes
```

命令先检查动态文字逻辑，再构建站点和导出 outputs/首页预览.html。Markdown 必填字段和状态值由内容集合检查；失败会停止，不应提交为成功结果。此命令不调用 AI、不自动写笔记，也不自动提交 Git。

开发预览运行时，保存 Markdown 会触发更新。离线 HTML 是快照，每次修改后要重新导出，并刷新或重新打开。Git 推送本身不会更新已打开的本地 HTML。

## Git 同步

每次由用户发出更新指令后执行。执行者核对本地与远程、审阅差异、完成验证，再提交本次变更并推送；出现不能判断的冲突先询问。推送失败保留本地内容并报告。生成目录已被忽略，GitHub 保存的是 Markdown 和源码。推送 main 会启动 GitHub Actions，部署成功后刷新线上网页即可看到更新。

构建失败时查看 Actions 日志并修复后重新推送。
